# 目标闭环（Goal / Step / Action / Memory）

## 适用与不适用

- 适用：需要两条以上命令、步骤之间有依赖，或失败后需要改变计划的运维任务。
- 不适用：单条只读查询，直接用 `pg_inspect`、`pg_catalog`、`kb_search`。

## 循环契约

1. 先调用 `bk_goal op open`：给出 `target`、`intent`（操作者原话）与拆解。拆解与约束写入控制库，会话结束不丢失。
2. 选择策略前调用 `bk_recall`：检索同一目标、同一失败签名的成功先例与教训。`bk_goal op open` 的返回值也带 `prior`，可直接引用。
3. 调用 `bk_step_run` 推进目标。它执行到下一个决策点，可能在同一调用中连续完成多个可运行步骤。
4. 返回值中的 `hint` 是下一步动作的唯一依据：

| hint | 含义 | 动作 |
|---|---|---|
| `run_step` | 仍有可运行步骤 | 再次调用 `bk_step_run` |
| `remediate` | 存在失败步骤且候选集开放 | 调用 `bk_remediate`，只能选择候选集内的处置 |
| `await_approval` | 下一个可运行步骤是未审批的破坏性动作 | 报出 step id，请操作者执行 `bkagent goal approve-step`；不得改用其它动作绕行 |
| `done` | 目标已到终态，或已转人工 | 汇总结果并停止 |

5. `hint` 与 `next` 不是同一件事：`next` 由调度器给出（当前是否可派发步骤），`hint` 由目标与步骤状态给出（本轮应当做什么）。两者不一致时以 `hint` 为准。
6. 失败时读取 `diagnosis.candidates`，只能从中选择。`replan` 必须提供通过 capability grammar 的新动作；`replan` 会清空该步骤已有的审批，替换后的破坏性动作需要重新执行 `goal approve-step`。
7. `escalate` 与 `abandon` 使目标进入终态，之后不再重试。

## 硬约束

- 不自行审批破坏性步骤。审批只能由人在 CLI 执行，模型与 MCP 都没有该通道。
- 不在执行开始后新增或删除步骤，只修正单个步骤。
- 步骤动作不得携带口令：`--dsn` 不带密码，凭据走 `BKAGENT_DSN`、`.pgpass`、peer 或 GSSAPI。动作会被持久化并在后续运行中重放。
- 目标失败不等于操作失败。报告诊断、候选集与已执行步骤，把决定交回操作者。

## 输出要求

- 目标 id、每个步骤的状态与尝试次数、目标终态。
- 失败时给出：错误类、失败签名、候选集、被选中的处置与理由。
- 引用的记忆条目：签名、对应动作、成功或失败的结论。
