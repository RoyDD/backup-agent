# 备份校验分级

| 等级 | 动作 | 证据 |
|---|---|---|
| V0 | 摘要/`pg_verifybackup`/`pgbackrest verify` | 产物完整、WAL 齐备 |
| V1 | `pg_restore --list` / 清单解析 | 目录项完整 |
| V2 | 恢复到临时实例，Schema 与行数比对 | 结构与数据一致 |
| V3 | 业务冒烟 SQL | 业务断言通过 |

## 流程

1. 备份完成后先做 V0；失败则产物标记不可用，不进入保留链。
2. 每日抽样做 V2，每周做 V3；provider/版本升级后首次备份必须 V2。
3. 调用 `pg_verify` 将逻辑备份恢复到临时库并比对各表行数；报告 `ok=false` 时不得宣称可恢复。
4. 只把最近通过 V2+ 的产物作为“已验证恢复点（VRP）”；RPO 达成率以 VRP 为准。

## 注意

- 行数一致不代表数据正确；关键表需补充校验和或业务断言。
- 序列值、扩展版本、属主与权限不在行数比对的覆盖范围内，需单独检查。
- 校验证据应记录环境指纹（PostgreSQL/provider 版本）；环境变化后证据失效。
