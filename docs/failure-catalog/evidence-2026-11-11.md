| Item | Value |

| Client host | Fedora 42 / WSL, psql 16.11 |
| PostgreSQL 16 | 16.15 (Debian), container `pgv16`, port 55416 |
| PostgreSQL 17 | 17.11 (Debian), container `pgv17`, port 55417 |

## E — Environment and privileges

### E-01 Wrong password

```
$ PGPASSWORD=wrong psql -h 127.0.0.1 -p 55416 -U postgres -d postgres -c 'select 1'
exit=2
psql: error: connection to server at "127.0.0.1", port 55416 failed:
FATAL:  password authentication failed for user "postgres"
```

### E-02 Unknown role

```
$ psql -h 127.0.0.1 -p 55416 -U ghost -d postgres -c 'select 1'
exit=2
FATAL:  password authentication failed for user "ghost"
```

Note: with scram, an unknown role is indistinguishable from a wrong password; this is
anti-enumeration behaviour, so the preflight must not claim to distinguish them.

### E-03 Unknown database

```
$ psql -h 127.0.0.1 -p 55416 -U postgres -d ghostdb -c 'select 1'
exit=2
FATAL:  database "ghostdb" does not exist
```

## S — Backup

### S-01 Dump a nonexistent database

```
$ pg_dump -h 127.0.0.1 -p 55416 -U postgres -d ghostdb -Fc -f ghost.dump
exit=1
pg_dump: error: connection to server ... failed:
FATAL:  database "ghostdb" does not exist
```

### S-02 Table privilege denied

Setup: role `bk_limited` (LOGIN), table `secret_t` owned by postgres.

```
$ PGPASSWORD=limited_pw pg_dump -h 127.0.0.1 -p 55416 -U bk_limited -d repro -t secret_t -Fc -f denied.dump
exit=1
pg_dump: error: query failed: ERROR:  permission denied for table secret_t
pg_dump: detail: Query was: LOCK TABLE public.secret_t IN ACCESS SHARE MODE
```

### S-03 Lock wait timeout

Setup: another session holds `ACCESS EXCLUSIVE` on `lock_t`; `--lock-wait-timeout=200`.

```
$ pg_dump ... -t lock_t --lock-wait-timeout=200 -Fc -f lock.dump
exit=1
pg_dump: error: query failed: ERROR:  canceling statement due to statement timeout
pg_dump: detail: Query was: LOCK TABLE public.lock_t IN ACCESS SHARE MODE
```

## R — Restore

### R-01 Dump newer than pg_restore

Setup: `pg_dump` 17.11 produces a custom-format dump; `pg_restore` 16.11 reads it.

```
$ pg_restore -l x17.dump
exit=1
pg_restore: error: unsupported version (1.16) in file header
```

### R-02 Owner role missing

Setup: table `owned_t` owned by `tmp_owner`; role dropped after the dump.

```
$ pg_restore -h 127.0.0.1 -p 55416 -U postgres -d repro owned.dump
exit=1
pg_restore: error: could not execute query: ERROR:  role "tmp_owner" does not exist
Command was: ALTER TABLE public.owned_t OWNER TO tmp_owner;
pg_restore: warning: errors ignored on restore: 1
```

### R-04 `--clean` against absent objects

Setup: dump of `clean_t`, then the table is dropped before restore.

```
$ pg_restore --clean -h 127.0.0.1 -p 55416 -U postgres -d repro clean.dump
exit=1
pg_restore: error: could not execute query: ERROR:  table "clean_t" does not exist
Command was: DROP TABLE public.clean_t;
pg_restore: warning: errors ignored on restore: 1
```

## P — Point-in-time recovery

Cluster: `initdb -A trust`, `wal_level=replica`, `archive_mode=on`,
`archive_command='cp %p /tmp/pitr_arch/%f'`, port 5555.
Base backup taken after the first `pg_switch_wal()`; rows 2..1000 inserted afterwards;
the newest archived segment (`000000010000000000000003`) was then deleted to simulate loss.
